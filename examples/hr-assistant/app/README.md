# hr-assistant

Tells employees how many days off they have left and books them

A Spring AI agent generated by [gen-agent](https://www.npmjs.com/package/gen-agent) (profile `standard`):
Spring Boot 4.1.1, Spring AI 2.0.1, Java 21.

## Run

Docker Compose starts the agent with Postgres, Redis and Keycloak:

```bash
OLLAMA_HOST=0.0.0.0 ollama serve &   # Ollama runs on this machine, reachable from the containers
ollama pull qwen2.5:7b
docker compose up --build
```

Every request needs a token. Sign in as the `demo` user of the Keycloak started by Compose (password `demo`):

```bash
TOKEN=$(curl -s localhost:8180/realms/agent/protocol/openid-connect/token \
  -d grant_type=password -d client_id=agent-client -d username=demo -d password=demo | jq -r .access_token)
curl -s localhost:8080/api/chat -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"message": "Hello"}'
```

Without Docker, Java 21 is enough to build: `./mvnw` downloads Maven (checked against its SHA-256).
Point the agent at your own services with environment variables:
`DATABASE_URL`, `DATABASE_USERNAME`, `DATABASE_PASSWORD` (Postgres),
`REDIS_URL`,
`OIDC_ISSUER_URI` (your identity provider: Keycloak, Auth0, Entra ID…),
then `./mvnw spring-boot:run`.

Send back the returned `conversationId` with the next message to continue the same conversation (the last
20 messages are kept in Postgres).
Conversations belong to the user of the token: another user gets 404 for them.
Every reply carries `"aiGenerated": true`, so clients can tell users they are talking to an AI (EU AI Act).

## Limits

- 30 requests per user and per minute.
- 100000 model tokens per user and per day, given back in full at the end of each day.

Beyond, the agent answers 429 with `Retry-After`. Change them under `agent.limits` in `application.yml`.

## Chat page

Open http://localhost:8080 to talk to the agent in a browser (sign in as `demo` / `demo` with Docker Compose).
The page is plain HTML, CSS and JavaScript in `src/main/resources/static`: change it as you like.
It signs users in with the authorization code flow and PKCE, through the public client `agent-client`
(`OIDC_CLIENT_ID`), and sends their token with each message: the agent keeps no session.

## Cache

The first answer of a conversation is kept in Redis for an hour (`agent.cache.ttl`): the same user asking the same
question again gets it without a call to the model. It is never shared between users, and an answer that used a tool is never kept: it depends on live data.

## Human control

Calls to `bookDayOff` wait for the approval of the user who asked: the reply lists them in
`approvals`, `GET /api/approvals` lists those still waiting, and `POST /api/approvals/{id}` with `{"approved": true}`
or `false` makes the call or not, tells the model and returns its next answer. A call nobody approves expires
(`approval.expiresAfter` in agent.yaml), and only the user who asked can decide. The chat page shows Approve and Deny buttons.

## Observability

Health and metrics answer on port 8081 (`MANAGEMENT_PORT`), not on the public one: `/actuator/health`, `/actuator/prometheus`.
Traces and metrics of every conversation (model calls, tools, tokens) go to OpenTelemetry when `OTLP_ENABLED` is
true: Docker Compose sends them to Grafana, at http://localhost:3000.

## Test

```bash
./mvnw verify
```

The tests use a fake model: they never call ollama and cost nothing.
Docker must run: the tests start Postgres and Redis in containers (Testcontainers).

## Where to put your code

| Path | Owner |
| --- | --- |
| `src/main/resources/prompts/system.md` | yours: the system prompt |
| `src/main/java/com/example/hrassistant/tool/` | yours: the logic of your Java tools |
| `src/main/java/com/example/hrassistant/generated/` | gen-agent: overwritten on regeneration, do not edit |
| `pom.xml`, `application.yml` | shared: gen-agent will merge its changes with yours |
