# claims-desk

Helps policyholders follow their insurance claims

A Spring AI agent generated by [gen-agent](https://www.npmjs.com/package/gen-agent) (profile `production`):
Spring Boot 4.1.1, Spring AI 2.0.1, Java 21.

## Run

Docker Compose starts the agent with Redis and Keycloak:

```bash
export ANTHROPIC_API_KEY=...   # never commit it
export OPENAI_API_KEY=...   # never commit it
docker compose up --build
```

Every request needs a token. Sign in as the `demo` user of the Keycloak started by Compose (password `demo`):

```bash
TOKEN=$(curl -s localhost:8180/realms/agent/protocol/openid-connect/token \
  -d grant_type=password -d client_id=agent-client -d username=demo -d password=demo | jq -r .access_token)
curl -s localhost:8080/api/chat -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"message": "Hello"}'
```

Without Docker, Java 21 is enough to build: `./mvnw` downloads Maven (checked against its SHA-256).
Point the agent at your own services with environment variables:
`REDIS_URL`,
`OIDC_ISSUER_URI` (your identity provider: Keycloak, Auth0, Entra ID…),
then `./mvnw spring-boot:run`.

Send back the returned `conversationId` with the next message to continue the same conversation (the last
20 messages are kept in memory).
Conversations belong to the user of the token: another user gets 404 for them.
Every reply carries `"aiGenerated": true`, so clients can tell users they are talking to an AI (EU AI Act).

## Limits

- 30 requests per user and per minute.
- 100000 model tokens per user and per day, given back in full at the end of each day.

Beyond, the agent answers 429 with `Retry-After`. Change them under `agent.limits` in `application.yml`.

## Cache

The first answer of a conversation is kept in Redis for an hour (`agent.cache.ttl`): the same user asking the same
question again gets it without a call to the model. It is never shared between users.

## Personal data

Emails, phone numbers, IBANs, card numbers (Luhn-checked) and French social security numbers never reach the model:
they are replaced by tokens such as `[EMAIL_1]` before each call, and put back in the answer and in the arguments of
the tools. The values behind the tokens stay in Redis for 30d (`agent.privacy.ttl`). Names and
addresses are not detected: keep them out of the system prompt, or mask them in your own code.

The logs mask the same values, in messages and in stack traces; each line carries the correlation id of its request.

## Resilience and cost

A failed call to the model is retried twice with a growing delay (`spring.ai.anthropic.max-retries`). After repeated
failures a circuit breaker opens for 30 seconds (`resilience4j.circuitbreaker`): requests stop waiting on a model that is
down. Meanwhile, and whenever a call fails, `gpt-5-mini` (openai) answers instead, through its own breaker.
When no model can answer, users get the fallback answer of `agent.fallback-answer`, never an error page.

Simple messages go to `claude-haiku-4-5`, the others to `claude-sonnet-5` (`agent.routing`):
`claude-haiku-4-5` itself tells first whether a message is simple; when it cannot tell, `claude-sonnet-5` answers.
The model of each call is in its trace.

Beyond 20 messages, the older ones of a conversation are summarized by the model (`claude-haiku-4-5`) and kept as one
message, so that a long conversation keeps its facts without sending them all again.

## Guardrails

A message that tries to take over the agent (ignore your instructions, show your system prompt, you are now…, fake
system or tool messages, in English or French, plainly or in base64) gets a refusal (`agent.guard.refusal`) and never
reaches the model.
These are heuristics: they make an attack harder, they do not rule it out. Never give the agent a tool whose misuse
you could not accept.

An answer that repeats the system prompt is replaced by the refusal, and API keys (OpenAI, AWS, GitHub…) are masked.

The model may call tools 8 times to answer one message (`spring.ai.tools.limits.max-total-tool-calls`);
beyond, the request stops with 422.

A request may take 60s at most (`agent.timeout`), model calls and tools included; beyond, it is stopped
and answered with 504.

## Observability

Health and metrics answer on port 8081 (`MANAGEMENT_PORT`), not on the public one: `/actuator/health`, `/actuator/prometheus`.
Traces and metrics of every conversation (model calls, tools, tokens) go to OpenTelemetry when `OTLP_ENABLED` is
true: Docker Compose sends them to Grafana, at http://localhost:3000.

## Test

```bash
./mvnw verify
```

The tests use a fake model: they never call anthropic and cost nothing.
Docker must run: the tests start Redis in containers (Testcontainers).

## Where to put your code

| Path | Owner |
| --- | --- |
| `src/main/resources/prompts/system.md` | yours: the system prompt |
| `src/main/java/com/example/claimsdesk/generated/` | gen-agent: overwritten on regeneration, do not edit |
| `pom.xml`, `application.yml` | shared: gen-agent will merge its changes with yours |
