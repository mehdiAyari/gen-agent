# Bug hunt

Scope (2026-10-30): look for the bugs the examples have not met yet, with methods that keep looking in CI. Every bug
found gets a failing test first, then its fix; the examples are run again at the end.

## Decisions

|     | Decision                                                                                                                                                                                                                                                                                                                                                                                       |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| H1  | Combinations. A property test (fast-check) draws hundreds of valid `agent.yaml` files and checks invariants on what gets generated: no template residue, no dead import, every Java type it refers to exists, valid YAML and JSON, every environment variable documented. A pairwise matrix of the options then builds about thirty projects (`test-compile`), a sample of them with `verify`. |
| H2  | Failures. A running agent with its dependencies cut on purpose: the model stopped mid-answer, Postgres, Redis and the identity provider down then back, an expired token, oversized and malformed input, concurrent users. Each scenario says what the user gets, and what it should get.                                                                                                      |
| H3  | Paths never walked: local and remote MCP servers, Gradle, routing and fallback for real, the Helm chart on kind, the web generator from the form to a running agent; a hosted provider if an API key is given.                                                                                                                                                                                 |
| H4  | Updates: a generated project changed the way users change it (their files, the shared ones), then regenerated after template changes; nothing of theirs may be lost.                                                                                                                                                                                                                           |
| H5  | Attacks: hundreds of prompt attacks (promptfoo), an OWASP ZAP scan of the API, cross-user access to every endpoint (conversations, approvals, feedback, erasure, documents, switches).                                                                                                                                                                                                         |
| H6  | Clean room: each README followed to the letter in a fresh container, with nothing installed but what it asks for.                                                                                                                                                                                                                                                                              |
