Part of the `production` profile plan (`2026-10-24-v5-production-profile.md`). Validated on 2026-10-25.
Tested down to `./mvnw verify`, tried for real with Ollama, and committed.

## Decisions

|     | Decision                                                                                                                                                                                                                                                           |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| R1  | Documents come from a `documents/` folder, indexed at startup (only what changed, by fingerprint; removed files are dropped), and from `POST` / `GET` / `DELETE /api/admin/documents` for the `agent-admin` role (with sign-in).                                   |
| R2  | Every format Apache Tika reads (PDF, Word, PowerPoint, HTML, Markdown, text…), through `spring-ai-tika-document-reader`; chunks of `chunkSize` tokens (500 by default).                                                                                            |
| R3  | `rerank: true`: 3 × `topK` passages are found, the model (the simple one with routing) scores them in one call, the `topK` best are kept; on any failure, the vector order is kept.                                                                                |
| R4  | The knowledge base is shared by every user of the agent.                                                                                                                                                                                                           |
| R5  | Documents reach the model as a system message, between `<document>` tags marked as data, never instructions; they are not kept in the conversation memory. A passage that holds prompt injection is never sent. Personal data in passages is masked like the rest. |
| R6  | RAG needs Postgres (pgvector, table `agent_document`) and a provider with embeddings; Postgres runs even when conversations are kept in memory.                                                                                                                    |
