# V5b — Robustness and guardrails

Part of the `production` profile plan (`2026-10-24-v5-production-profile.md`, decisions D, E, F, J, K, L). Validated on 2026-10-24. Three
deliveries, each tested down to `./mvnw verify`, tried for real with Ollama, and committed.

| Delivery                   | Content                                                                                                              |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| V5b1 — Guardrails          | Prompt injection detection, untrusted tool results, output guardrails, loop limits (`maxIterations`, `timeout`)      |
| V5b2 — Resilience and cost | Retries with backoff, circuit breaker, fallback provider then fallback answer, model routing, conversation summaries |
| V5b3 — Control             | Human approval of tool calls, kill switches for the agent and each tool                                              |

## Decisions

|     | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | `security.injectionDetection`: heuristic rules in English and French (ignore previous instructions, reveal the system prompt, role play as…, fake system or tool tags, encoded payloads). A user message that matches is not sent to the model: the agent answers a polite refusal (200), counted in the metrics.                                                                                                                                                    |
| D2  | Tool results go to the model between delimiters marking them as untrusted data, with a system prompt note. A tool result that matches the rules taints the request: tools with side effects (POST, PUT, PATCH, DELETE, approval) are refused for the rest of it.                                                                                                                                                                                                     |
| D3  | Output guardrails: a canary in the system prompt; an answer holding the canary or a long verbatim part of the system prompt is replaced by a refusal; secrets (the key patterns of core) are masked in answers. Key added to the format: `security.outputGuard`, on in production.                                                                                                                                                                                   |
| L1  | `limits.maxIterations` counts tool calls per request (beyond: the tools answer that the limit is reached); `limits.timeout` bounds the whole request (504 with a problem detail). Production: 8 and 60s.                                                                                                                                                                                                                                                             |
| J1  | Retries: the retry of Spring AI (`spring.ai.retry`, exponential backoff). Circuit breaker and time limiter per provider: Resilience4j 2.4.0 (`resilience4j-spring-boot4`, built on Boot 4.0).                                                                                                                                                                                                                                                                        |
| J2  | `model.fallback`: a second chat model, used when the first fails or its breaker is open; then a fallback answer from `application.yml` (503 is never shown raw). `gdpr.euOnly` already applies.                                                                                                                                                                                                                                                                      |
| F1  | `model.routing`: same provider, `simple` and `complex` model names. `rules`: length, code, several questions, history; `classifier`: the simple model answers `simple` or `complex` first. The chosen model is in the traces.                                                                                                                                                                                                                                        |
| S1  | `memory.summarize`: once the window is full, older messages are summarized by the model (the simple one with routing) and kept as one message.                                                                                                                                                                                                                                                                                                                       |
| E1  | `approval.required`: the call is kept in Postgres (`agent_approval`) with its masked arguments; the reply says what waits. `GET /api/approvals` lists the user's pending calls; `POST /api/approvals/{id}` with `approve` or `deny` runs it or not, adds the outcome to the conversation and returns the model's next answer. Expired after `expiresAfter`. Only the user who asked can approve. The chat page shows the pending call with Approve and Deny buttons. |
| K1  | Kill switches as Redis flags read on each request: the agent off answers 503 with the fallback answer; a tool off answers the model that it is disabled. Admin endpoints for the `agent-admin` role. Key added to the format: `security.killSwitches`, on in production.                                                                                                                                                                                             |
